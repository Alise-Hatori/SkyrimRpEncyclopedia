# Приёмка внутренней сборки

Автоматические проверки не означают визуальную приёмку. Статус каждого пункта
записывается отдельно: пройдено / не пройдено / не проверено, с наблюдением.

## Автоматически

- Release-сборка приложения и smoke-проекта с `--no-restore`.
- Полный smoke с явными `SKYRIM_RP_MVP_DB` и
  `SKYRIM_RP_TEST_MVP_EXPECTED_ENTITY_COUNT`: legacy 125 и Knowledge 5579.
  Размер не вычисляется из той же базы вместо ожидания.
- Временные базы: CRUD, транзакции метаданных, искусственные отказы записи,
  отклонение чужих/повреждённых файлов, история по источникам.
- Контроль SHA-256 пяти реальных баз до и после; отсутствие их в publish-каталоге.
- В комплекте нет журналов, баз/sidecar, PDB, исходников тестов и секретов.

## Вручную в изолированном процессе

1. Первый запуск: окно открывается; выбран правильный корпус; нет исключений.
2. Перейти по всем разделам после каталога, карты и главной: активная кнопка и
   видимая область соответствуют разделу, старое содержимое не остаётся поверх.
3. Поиск, фильтры нескольких тегов/флагов и источников: точное пересечение;
   пустой результат объясним. Открыть статью, вернуться: заголовок/запрос/scroll.
4. История: открыть личную, официальную и Knowledge-статью; повторить открытие;
   проверить порядок. При отказе истории статья остаётся открытой.
5. Создать, изменить и удалить личную статью; теги/категории согласованы после
   переименования. Создать/изменить/удалить заметки; проверить пакетный список.
6. Конструктор: создать и сохранить ивент дважды — одна запись. В библиотеке
   открыть редактирование, обновить, удалить тестовый ивент; начать новый черновик.
7. Простые ивенты: генерация, точный replay, независимое копирование публичного
   объявления/заметок. При ошибке новые параметры не маскируются старым результатом.
8. Сценарии: пять жанров, seed, начальная «Средняя» сложность, опоры, копирование,
   JSON round-trip. Фабрики и канонические статусы не меняются.
9. Атлас: поиск, раскрытие, полная карта, фильтры, zoom/pan и переход к статье.
10. Карта/мини-карта и overlay: проверить существующее поведение без улучшений.
    Сетевые действия — только отдельно разрешённая проверка пользователя.
11. ИИ-помощник: только текущая базовая работоспособность; запрос к модели —
    отдельная разрешённая ручная проверка, не часть офлайн-автоматического прогона.
12. На тестовых данных вызвать отказ сохранения: понятное сообщение, ввод не
    теряется, нет частичной записи или дубликата. Не менять ACL рабочих баз.
13. Штатно закрыть и повторно открыть с теми же изолированными путями. Личные
    статьи/заметки/ивенты сохранились; контрольный корпус неизменен.

## Чистая Windows и выпуск

- Отдельная Windows без SDK/Visual Studio: установка Desktop Runtime и WebView2,
  запуск всего опубликованного каталога обычным пользователем.
- Проверка архитектуры, отсутствующих runtime, недоступного корпуса и папки записи.
- Проверка сохранности данных при обновлении (не заменять user/official файлы).
- Подтверждение лицензий зависимостей, изображений/шрифтов, текста и корпуса Wiki.

Эти пункты не считаются пройденными, пока нет фактических результатов. Публичный
релиз блокируется до ручной приёмки, чистой установки и закрытия прав на контент.
